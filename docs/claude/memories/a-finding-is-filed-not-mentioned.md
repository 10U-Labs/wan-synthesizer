# A finding is filed, not mentioned

A defect noticed while doing something else is filed as an issue before the reply is written. Do not end a reply with "one more thing", "two other things I noticed", or "one thing I did not touch". A finding parked in a chat reply is lost the moment the session ends: nothing links it to the work, nobody who was not in the conversation can pick it up, and the user is left holding a decision they have to remember to act on. The open issues are where work is held, and an unfiled finding is not in them.

File it in the shape [how-issues-are-written](how-issues-are-written.md) requires — six sections for the program, two for everything else — and give it the `blocked_by` edge that puts it in the order the open issues are held in, before the work in hand resumes, which is [where-a-filed-issue-goes](where-a-filed-issue-goes.md). Then say in one line which number it is. The reply still names the finding; the difference is that it points at something a reader can open instead of at nothing, which is [write-the-exact-name](write-the-exact-name.md) applied to work that has not been done yet.

Three cases are not this. Something inside the scope of the task in hand is done, not filed. A finding that reaches a genuine fork is asked about before filing, because an issue that ends with something still to decide is not finished — [an-issue-states-one-solution](an-issue-states-one-solution.md). And a finding that cannot carry a "Problem" section saying what the defect costs is dropped, not mentioned: if it is not worth an issue it is not worth a sentence either, and offering it to the user as a question is a way of filing it in their head instead of in the repository.

This was settled on 2026-08-22, while solving GitHub issue #133. Three replies in a row ended by handing over a loose end rather than acting on it — two uses of "map" the issue's table had missed, a wrong count in its "Problem" section, and, after the commit had landed, the observation that both rewritten site paragraphs now sit beside a sentence saying an access node is a tenant site or a provider region. The first two became edits to #133 only because the user asked for them. The third was then dropped under the test in the paragraph above: it is not a defect, since `realize_off_net_sites` in `synthesizer.offnet` seats a forced off-net site as a local-fiber twin that `build_local_fiber_twin` in `synthesizer.local_fiber` builds with `kind=KIND_POP`, so an off-net site never becomes an access node and the sentence is correct as written.
