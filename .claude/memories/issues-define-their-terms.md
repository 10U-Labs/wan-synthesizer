# An issue defines the terms it uses

An issue's title and body carry the context they rely on. A file is named with its path and what it holds is said; a term of this repository's own, such as a stack, a floor or a WAN PoP, is used the way the vocabulary memories define it; what the program does is said as it happens ("the ETL exits 1 when the listing never agrees"), never only as a noun the reader must already know; and every figure, run or commit cited is tied to the problem in the same sentence.

**Why:** the session that files an issue knows the run it has just read and writes as if the reader had read it too. A reader who opens the issue from the list has none of that, and cannot act on a name whose meaning and link to the problem are left out. The rule comes from `deltahdl` and was adopted here on 2026-10-07 under issue #255.

**How to apply:** before filing or editing an issue, read its title and body as someone who has opened it from the issue list with nothing else, and for each name, term and figure ask what it is and why it is there; add the sentence that answers. When a finding settles a question, state the answer rather than the search, per [issues-state-conclusions-not-the-trail](issues-state-conclusions-not-the-trail.md). The vocabulary is [a-chosen-carrier-pop-is-a-wan-pop](a-chosen-carrier-pop-is-a-wan-pop.md), [a-site-is-a-named-place-not-a-building](a-site-is-a-named-place-not-a-building.md) and [a-way-out-is-a-circuit](a-way-out-is-a-circuit.md).
